| 2026-09-25 | Derived memories and participant labels | "Union of sources' labels" is right for identity and location (all must be held) but wrong for participants (any one suffices): the union would let a witness of one source read content from another source they never witnessed. Proposed rule: a derived memory is readable only by an agent who could read every source. So identity and location labels take the union, and participant labels take the **intersection** of the sources' participant sets. An empty intersection means no participant can read it unless the environment relaxes it, e.g. into personal memory (Claude) | accepted (Gus, 2026-09-25) | Gus's example: after {A, B} and {A, C}, a new conversation {A, B, C} happens. C must not be able to recall or synthesise the earlier {A, B} conversation. But anything said in {A, B, C} is fair game, even if it is semantically close to {A, B}: A and B could simply tell C, and C may remember what was said. See [[Label and Memory Types]]. |
| 2026-09-25 | Consolidation across label sets | The memory system never merges, deduplicates or updates across different label sets, however similar the content. A fact from {A, B, C} that matches an {A, B} memory stays a separate memory, linked by provenance (A recalled the {A, B} memory when speaking) rather than merged. Disclosure happens only when agents speak, never through the memory system's background processes (Claude) | accepted (Gus, 2026-09-25): merging within a label set is fine, between label sets it is not. Cross-label-set merges may be allowed in some cases later; a future idea | Follows from Gus's example. A merge would either leak {A, B} content to C (union) or take away C's own memory of {A, B, C} (intersection). Mem0's add-time lookup and Hindsight's widening scope modes are exactly this failure; Hindsight's default "combined" scope and AgentCore's strictly-consistent keys avoid it. |
